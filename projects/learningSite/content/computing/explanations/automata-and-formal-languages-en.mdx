A finite automaton is deliberately one of the simplest machines imaginable: it has some fixed number of internal states, it reads its input one symbol at a time, and after reading each symbol it transitions to a new state determined entirely by its current state and that symbol. That's the entire machine -- no separate memory, no scratchpad, nothing beyond "which state am I currently in." A string is accepted if, after reading every symbol in it, the automaton ends up in one of its designated accepting states.

This extreme restriction is precisely what makes finite automata theoretically interesting rather than just a toy: it draws a sharp, provable line between problems this simple machine can solve and problems it provably cannot, no matter how cleverly it's designed or how many states it's given. The set of strings a given finite automaton accepts is called a regular language, and a surprising number of genuinely useful pattern-matching tasks turn out to be regular -- validating that a string has the rough shape of an email address, recognizing keywords while tokenizing source code, and most of what a typical regular-expression search actually does. But other problems that sound almost identical are provably impossible for any finite automaton: recognizing "balanced parentheses nested to arbitrary depth" requires tracking how many unmatched open parentheses have been seen so far, a count that can grow without bound as the input grows, and a machine whose only memory is one of a fixed, finite number of states simply cannot represent an unboundedly large count -- there just aren't enough states, no matter how many you're willing to add.

The Chomsky hierarchy generalizes exactly this kind of question into a full ladder of language classes, each one defined by how much computational power is needed to recognize it. Regular languages sit at the bottom, recognized by finite automata. Context-free languages (which include balanced-parentheses-style nesting) sit one level up, recognized by a pushdown automaton -- a finite automaton augmented with exactly the unbounded stack-like memory a finite automaton lacks. Context-sensitive and unrestricted languages sit higher still, requiring progressively more powerful machines. The hierarchy isn't a naming convention -- it's a precise, formal answer to "how much memory and what kind of memory does recognizing this particular language actually require," a question theory of computation can answer rigorously rather than by intuition alone.
