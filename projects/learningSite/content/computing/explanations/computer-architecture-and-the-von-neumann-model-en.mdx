The von Neumann architecture's single defining idea is deceptively simple: a program's instructions and the data those instructions operate on live in the same memory, addressed the same way, so that memory can hold either -- or, from the hardware's point of view, doesn't even distinguish between the two until an instruction is actually fetched and interpreted as one. This is precisely what makes a computer general-purpose rather than fixed-function: reprogramming it for an entirely new task means loading a different sequence of instructions into that same memory, not physically rewiring anything, which is exactly why the same physical machine can run a spreadsheet, a game, or a web browser without any hardware change at all.

Running a program is a continuously repeating cycle with three stages. Fetch: the CPU reads the instruction sitting at the memory address its program counter currently points to. Decode: control circuitry interprets that instruction's bit pattern to determine which operation it specifies and which registers or memory locations it involves. Execute: the CPU actually performs that operation, which might mean doing arithmetic in its arithmetic logic unit, moving data between a register and memory, or altering the program counter itself (a jump or branch). The program counter then advances to the next instruction, and the whole cycle repeats -- billions of times per second in a modern CPU, with real hardware overlapping several instructions' stages simultaneously (pipelining) as long as doing so doesn't change the program's observable result.

The memory hierarchy exists because of a hard economic and physical constraint: no single memory technology is simultaneously large-capacity, cheap, and fast enough to keep up with the CPU on every single access. So real systems build a hierarchy instead -- a handful of registers built directly into the CPU, which are the fastest and most expensive per byte and hold only whatever the CPU is working with right this instant; a small cache just outside the CPU, larger but slower; main memory (RAM), larger still and slower again; and disk storage, vastly larger and vastly slower than any of the above. Each layer trades capacity for speed, and the system is designed so that whatever data is actually being used right now tends to sit in the fastest layer that can hold it, which is what lets a computer feel fast overall despite its slowest storage layer being, in absolute terms, extremely slow.
