Machine learning problems split along a basic line: does the training data come with known correct answers attached, or not? Supervised learning uses labeled data -- each training example already paired with the answer the model is trying to learn to predict -- and learns a mapping it can apply to new, unlabeled examples. Unsupervised learning works with data that has no such labels at all, looking instead for structure the data has on its own: natural groupings (clustering), or a simpler underlying representation of otherwise complex data.

Whichever type is used, evaluating a model's performance only on the data it was trained on is a trap, because a model can always be made to fit its own training data more closely, right up to memorizing it, which will look impressive but says nothing about how the model handles anything new. The standard defense is a held-out test set: data the model played no role in fitting, evaluated only after training is complete, giving an honest read on how the model actually generalizes.

This is the practical shape of the bias-variance tradeoff. A model too simple to capture the real relationship in the data -- underfitting, or high bias -- performs poorly on both training and new data, because it genuinely can't represent the pattern. A model flexible enough to fit the training data's specific noise and quirks -- overfitting, or high variance -- can look excellent on training data while performing far worse on anything new, since what it "learned" was partly the accidental noise in one particular dataset rather than the real underlying signal. Finding a model with enough capacity to capture the genuine pattern, but not so much that it starts fitting noise instead, is the central practical balancing act machine learning is built around -- and the gap between training accuracy and held-out test accuracy is exactly the tool used to detect when that balance has failed.
